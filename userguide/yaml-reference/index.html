    YAML Reference¶

    Project-level fields¶

    version: "1.0"          # required; must be "1.0"
name: my_project        # required; alphanumeric + hyphens/underscores; used as filename prefix

defaults:               # applied to every DAG unless overridden at DAG level
  max_active_runs: 1
  tags: [team_tag]
  group: etl            # default output sub-directory
  default_args:
    owner: my_team
    retries: 1
    retry_delay_minutes: 5
    email_on_failure: false

custom_operators:       # non-standard operators used in this project
  - name: MyOp
    import_path: "plugins.my_module.MyOp"
    description: "optional description"

task_library:           # reusable task snippets — see Templates & Reuse
  - id: log_done
    operator: BashOperator
    params:
      bash_command: "echo done"

dag_templates:          # reusable DAG patterns — see Templates & Reuse
  - id: standard_etl
    schedule: "0 2 * * *"
    pre_tasks: [...]
    post_tasks: [...]

dags:                   # required; at least one DAG
  - ...

    DAG fields¶

    Field Type Required Description
    id string yes Unique DAG identifier; alphanumeric and underscores only
    description string no Short description shown in the Airflow UI DAG list
    schedule string no Cron expression (e.g. 0 2 * * *) or preset (@daily, @hourly, @weekly, @monthly)
    start_date string no DAG start date in YYYY-MM-DD format
    end_date string no Optional end date; no new runs are scheduled after this date (YYYY-MM-DD)
    catchup boolean no Backfill missed intervals between start_date and today on first deploy (default: false)
    max_active_runs integer ≥1 no Maximum number of concurrent DAG runs (default: 16)
    group string no Output sub-directory for this DAG (overrides project default)
    tags list of string no UI filter tags; merged with project-level tags (deduped)
    enabled_envs list of string no Whitelist of environment names; DAG is only generated when the active environment appears in this list. Absence of this field means all environments are allowed.
    enabled_classes list of string no Whitelist of environment classes (e.g. non-production, staging, production); DAG is only generated when the active environment's class appears in this list. Use this instead of enabled_envs when you want env-name independence.
    _env object no Per-environment overrides for DAG-level scheduling fields (schedule, catchup, max_active_runs, tags). Keys are environment names; values are the fields to override.
    doc_md string no Markdown documentation rendered in the Airflow UI DAG detail view
    dag_display_name string no Human-readable display name shown in the Airflow 3.2+ UI (overrides dag_id)
    render_template_as_native_obj boolean no When true, Jinja-templated fields are rendered as native Python objects instead of strings
    on_failure_callback string no Dotted import path to a callable invoked when the DAG fails (e.g. plugins.alerts.notify)
    on_success_callback string no Dotted import path to a callable invoked when the DAG succeeds
    on_sla_miss_callback string no Dotted import path to a callable invoked on SLA miss

    Note

    enabled, default_args, tasks, extra_tasks, template, vars, and datasets are structural fields covered in dedicated sections below.

    Task fields¶

    Field Type Required Description
    id string no Unique task identifier within the DAG; alphanumeric and underscores only
    use string no Reference to a task_library entry id; library fields are merged as defaults
    operator string no Operator class name — standard built-in or registered custom operator
    doc string no Task-level documentation shown in the Airflow UI task detail view
    dependencies list of string no List of upstream task ids; generates upstream >> this_task edges
    trigger_rule string no Rule determining when this task is triggered relative to its upstream tasks — all_success, all_failed, all_done, all_skipped, one_success, one_failed, one_done, none_failed, none_skipped, none_failed_min_one_success, always, dummy
    pool string no Airflow pool name used to limit concurrency for this task
    pool_slots integer ≥1 no Number of pool slots this task occupies (default: 1)
    queue string no Celery/Kubernetes queue this task is submitted to
    priority_weight integer ≥1 no Task priority — higher values run first when the pool/executor has capacity
    weight_rule string no Algorithm for computing effective priority_weight across the DAG — downstream, upstream, absolute, exponential
    execution_timeout_minutes integer ≥1 no Maximum runtime in minutes before the task instance is killed and marked failed
    sla_minutes integer ≥1 no Expected maximum duration in minutes; triggers on_sla_miss_callback when exceeded
    on_failure_callback string no Dotted import path to a callable invoked when this task fails
    on_success_callback string no Dotted import path to a callable invoked when this task succeeds
    on_retry_callback string no Dotted import path to a callable invoked when this task is retried
    _env object no Per-environment overrides for task-level scheduling/execution fields (trigger_rule, pool, pool_slots, queue, priority_weight, weight_rule, execution_timeout_minutes, sla_minutes). Keys are environment names; values are the fields to override. Use params._env for arbitrary operator params.

    Note

    params, enabled, dynamic_map, and datasets are covered in dedicated sections below.

    trigger_rule values:

    Value Meaning
    all_success (default) All upstream tasks succeeded
    all_failed All upstream tasks failed
    all_done All upstream tasks finished (any state)
    all_skipped All upstream tasks were skipped
    one_success At least one upstream task succeeded
    one_failed At least one upstream task failed
    one_done At least one upstream task finished
    none_failed No upstream task failed or upstream-failed
    none_skipped No upstream task was skipped
    none_failed_min_one_success None failed and at least one succeeded
    always Run regardless of upstream state
    dummy Deprecated alias for always

    Example — task with scheduling fields:

    - id: critical_load
  operator: PythonOperator
  params:
    python_callable: "dags.etl.load"
  trigger_rule: all_done
  pool: db_pool
  pool_slots: 2
  queue: high_memory
  priority_weight: 10
  execution_timeout_minutes: 30
  sla_minutes: 45
  on_failure_callback: "plugins.alerts.pagerduty_alert"
  dependencies: [transform]

    Callable resolution: python_callable and callbacks¶

    python_callable (in params) and every on_*_callback field share one mechanism: you write a dotted path — module.submodule.function_name — and the generator:

    1. Splits it at the last dot into a module (module.submodule) and a name (function_name).
    2. Emits from module.submodule import function_name once at the top of the file (deduplicated even if several tasks import different names from the same module).
    3. References the bare function_name at the call site — never the full dotted path.

    So python_callable: "dags.pipeline.process_record" becomes:

    from dags.pipeline import process_record
...
python_callable=process_record,   # not dags.pipeline.process_record

    The path must contain at least one dot

    A value with no dot (e.g. python_callable: "process_record") has nothing to split into a module — the generator silently skips the import and emits the bare name as-is. Because this is a name-resolution problem, not a syntax error, it passes python3 -m py_compile and make validate and only fails as NameError: name 'process_record' is not defined when Airflow actually parses the DAG. Always use a fully-qualified module.function path.

    Avoid a task id that matches its own callable's function name

    If a task's id is identical to the imported function's name (e.g. id: process_record calling python_callable: "dags.pipeline.process_record"), the generated line process_record = PythonOperator(..., python_callable=process_record) reassigns process_record from the imported function to the operator object. That single line still works (Python evaluates the right-hand side first), but if a later task in the same file also needs process_record as a python_callable, it would now resolve to the operator instance instead of the function. Give the task a different id from its callable's function name if the same function is reused elsewhere in the DAG.

    default_args fields¶

    Field Type Description
    owner string Task owner displayed in the Airflow UI
    retries integer ≥0 Number of automatic retries before the task is marked as failed
    retry_delay_minutes integer ≥0 Wait time in minutes between retry attempts
    email_on_failure boolean Send an email alert when a task instance fails
    email string or list of string Email address or list of addresses for failure/retry alerts
    email_on_retry boolean Send email on task retry (default: true in Airflow)
    depends_on_past boolean Task only runs if the previous run of the same task succeeded
    execution_timeout_minutes integer ≥1 Maximum runtime per task instance in minutes before it times out

    Note

    Use _env inside default_args to override any of these fields per environment — see Environments.

    default_args:
  owner: data_team
  retries: 2
  retry_delay_minutes: 10
  email_on_failure: true
  email:
    - oncall@company.com
    - team@company.com
  email_on_retry: false
  depends_on_past: false
  execution_timeout_minutes: 60
  _env:
    prod:
      retries: 5
      execution_timeout_minutes: 120

    Dynamic task mapping (requires Airflow 3.0+)¶

    Generates Airflow 3's .partial().expand() or .partial().expand_kwargs() pattern. The map_index_template field requires Airflow 3.0+.

    expand — map over individual arguments:

    - id: process_record
  operator: PythonOperator
  params:
    python_callable: "dags.pipeline.process_record"
  dynamic_map:
    expand:
      record: "{{ fetch_records.output }}"   # raw Python expression
    map_index_template: "record_{{ ti.map_index }}"
  dependencies: [fetch_records]

    Generated Python: 

    from dags.pipeline import process_record   # auto-added — see note below

process_record = PythonOperator.partial(
    task_id="process_record",
    python_callable=process_record,
).expand(
    record=fetch_records.output,
)
process_record.map_index_template = "record_{{ ti.map_index }}"

    expand_kwargs — map over a list of dicts:

    - id: run_job
  operator: PythonOperator
  params:
    python_callable: "dags.pipeline.run_job"
  dynamic_map:
    expand_kwargs: "{{ get_job_configs.output }}"
  dependencies: [get_job_configs]

    Generated Python: 

    from dags.pipeline import run_job

run_job = PythonOperator.partial(
    task_id="run_job",
    python_callable=run_job,
).expand_kwargs(get_job_configs.output)

    Warning

    expand and expand_kwargs are mutually exclusive — use one per task.

    Asset outlets and inlets (requires Airflow 3.0+)¶

    Declare Airflow 3 Asset dependencies to enable data-driven DAG scheduling. Assets replace the Airflow 2.x Dataset concept — the generator emits from airflow.sdk import Asset automatically when any task declares outlets or inlets.

    tasks:
  - id: produce_report
    operator: PythonOperator
    params:
      python_callable: "dags.reporting.produce"
    datasets:
      outlets:
        - uri: "s3://reports-bucket/daily/report.csv"
      inlets:
        - uri: "s3://source-bucket/raw/events.json"

    Generated Python: 

    from airflow.sdk import Asset          # auto-added when outlets/inlets are present
from dags.reporting import produce     # auto-added — see note below

produce_report = PythonOperator(
    task_id="produce_report",
    python_callable=produce,
    outlets=[Asset("s3://reports-bucket/daily/report.csv")],
)

    Note

    inlets are declared on the task for lineage tracking. outlets additionally drive data-aware scheduling — a downstream DAG that declares schedule: <asset-uri> will be triggered automatically when this task completes.
