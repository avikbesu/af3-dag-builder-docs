    Advanced Features¶

    Complete worked example¶

    A production-grade project using project defaults, templates, task library, environment overrides, dynamic mapping, assets, callbacks, and pool control.

    version: "1.0"
name: data_platform

defaults:
  max_active_runs: 2
  tags: [data_platform]
  default_args:
    owner: data_team
    retries: 1
    retry_delay_minutes: 10
    email_on_failure: false
    email: oncall@company.com
    _env:
      prod:
        retries: 3
        email_on_failure: true
        execution_timeout_minutes: 90

dag_templates:
  - id: standard_etl
    schedule: "0 3 * * *"
    catchup: false
    pre_tasks:
      - id: check_source
        operator: PythonOperator
        params:
          python_callable: "dags.common.check_source"
    post_tasks:
      - id: send_notification
        operator: BashOperator
        params:
          bash_command: "echo '{{ pipeline }} complete'"

task_library:
  - id: write_audit
    operator: PythonOperator
    params:
      python_callable: "dags.common.write_audit"
      level: INFO

dags:
  # ── Daily ingest with dynamic mapping ─────────────────────────────────────
  - id: data_platform_ingest
    description: "Ingest events, process each dynamically, publish to asset"
    schedule: "@daily"
    start_date: "2025-01-01"
    catchup: false
    dag_display_name: "Daily Event Ingest"
    doc_md: |
      Fetches events from the API, processes each event in parallel using
      dynamic task mapping, and publishes the result as a Data Asset.
    on_failure_callback: "plugins.alerts.critical_failure"

    enabled:
      dev: true
      staging: true
      prod: true

    tasks:
      - id: fetch_events
        operator: PythonOperator
        params:
          python_callable: "dags.ingest.fetch_events"
        datasets:
          outlets:
            - uri: "s3://data-platform/raw/events"

      - id: process_event
        operator: PythonOperator
        params:
          python_callable: "dags.ingest.process_event"
        dynamic_map:
          expand:
            event: "{{ fetch_events.output }}"
          map_index_template: "event_{{ ti.map_index }}"
        pool: processing_pool
        pool_slots: 1
        execution_timeout_minutes: 15
        trigger_rule: all_success
        on_failure_callback: "plugins.alerts.task_failure"
        dependencies: [fetch_events]

      - use: write_audit
        id: audit
        params:
          level: DEBUG
          _env:
            prod:
              level: INFO
        dependencies: [process_event]

  # ── Templated ETL ─────────────────────────────────────────────────────────
  - id: data_platform_sales_etl
    template: standard_etl
    start_date: "2025-01-01"
    vars:
      pipeline: "sales"
    enabled:
      dev: true
      staging: true
      prod: true
    tasks:
      - id: extract
        operator: PythonOperator
        params:
          python_callable: "dags.etl.sales.extract"
          _env:
            prod:
              python_callable: "dags.etl.sales.extract_prod"
      - id: transform
        operator: PythonOperator
        params:
          python_callable: "dags.etl.sales.transform"
        dependencies: [extract]
      - id: load
        operator: PythonOperator
        params:
          python_callable: "dags.etl.sales.load"
        pool: db_write_pool
        priority_weight: 10
        dependencies: [transform]
    extra_tasks:
      - use: write_audit
        id: sales_audit
        dependencies: [send_notification]

    Airflow 3.2.2 feature examples¶

    Complete dags.yaml DAG definitions for every Airflow 3.x feature supported by the generator, each paired with the Python code that is produced.

    dag_display_name — human-readable DAG name (Airflow 3.2+)¶

    dag_id must be unique and follow Python identifier conventions. dag_display_name lets you show a friendlier label in the Airflow UI without changing the dag_id.

    YAML:

    version: "1.0"
name: reporting

dags:
  - id: reporting_weekly_sales_v2
    dag_display_name: "Weekly Sales Report (v2)"
    description: "Generates and distributes the weekly sales summary"
    schedule: "0 6 * * 1"
    start_date: "2025-01-01"
    catchup: false
    tags: [reporting, sales]
    default_args:
      owner: data_team
      retries: 2
      retry_delay_minutes: 5
      email_on_failure: true
      email: oncall@company.com
    tasks:
      - id: generate_report
        operator: PythonOperator
        params:
          python_callable: "dags.reporting.generate_weekly_sales"
      - id: send_report
        operator: PythonOperator
        params:
          python_callable: "dags.reporting.send_weekly_sales"
        dependencies: [generate_report]

    Generated Python (key DAG constructor fields):

    with DAG(
    dag_id="reporting_weekly_sales_v2",
    description="Generates and distributes the weekly sales summary",
    schedule="0 6 * * 1",
    start_date=datetime(2025, 1, 1),
    catchup=False,
    max_active_runs=16,
    tags=["reporting", "sales"],
    default_args=default_args,
    dag_display_name="Weekly Sales Report (v2)",   # ← shown in Airflow UI
) as dag:
    ...

    Note

    The Airflow UI displays Weekly Sales Report (v2) in the DAG list and detail page. The scheduler, logs, and API still reference reporting_weekly_sales_v2 as the identifier.

    Asset outlets — publishing data availability (Airflow 3.0+)¶

    Declaring an outlet on a task registers that task as a publisher of a named Asset. Airflow records a data event when the task completes successfully, which can then trigger downstream data-aware DAGs.

    YAML:

    version: "1.0"
name: ingestion

dags:
  - id: ingestion_daily_events
    description: "Ingest raw events from the API and publish to the data lake"
    schedule: "@daily"
    start_date: "2025-01-01"
    catchup: false
    tags: [ingestion]
    default_args:
      owner: data_eng
      retries: 3
      retry_delay_minutes: 10
      email_on_failure: true
      email: data-eng@company.com
    tasks:
      - id: fetch_events
        operator: PythonOperator
        params:
          python_callable: "dags.ingestion.fetch_events"

      - id: write_to_lake
        operator: PythonOperator
        params:
          python_callable: "dags.ingestion.write_events_to_lake"
        datasets:
          outlets:
            - uri: "s3://data-lake/events/daily"
        dependencies: [fetch_events]

    Generated Python (outlet task):

    from airflow.sdk import Asset   # auto-added by generator
from dags.ingestion import fetch_events
from dags.ingestion import write_events_to_lake

with DAG(...) as dag:

    fetch_events = PythonOperator(
        task_id="fetch_events",
        python_callable=fetch_events,
    )

    write_to_lake = PythonOperator(
        task_id="write_to_lake",
        python_callable=write_events_to_lake,
        outlets=[Asset("s3://data-lake/events/daily")],  # ← data event published on success
    )

    fetch_events >> write_to_lake

    Asset inlets — declaring lineage dependencies (Airflow 3.0+)¶

    inlets annotate a task with the Assets it reads. This is used for lineage tracking in the Airflow UI — it does not affect scheduling.

    YAML:

    version: "1.0"
name: transform

dags:
  - id: transform_daily_events
    description: "Transform raw events into the analytics schema"
    schedule: "@daily"
    start_date: "2025-01-01"
    catchup: false
    tags: [transform]
    default_args:
      owner: data_eng
      retries: 2
      retry_delay_minutes: 5
      email_on_failure: true
    tasks:
      - id: transform_events
        operator: PythonOperator
        params:
          python_callable: "dags.transform.transform_events"
        datasets:
          inlets:
            - uri: "s3://data-lake/events/daily"
          outlets:
            - uri: "s3://data-lake/events/transformed"

      - id: validate_output
        operator: PythonOperator
        params:
          python_callable: "dags.transform.validate_output"
        dependencies: [transform_events]

    Generated Python (task with both inlet and outlet):

    from airflow.sdk import Asset
from dags.transform import transform_events

    transform_events = PythonOperator(
        task_id="transform_events",
        python_callable=transform_events,
        outlets=[Asset("s3://data-lake/events/transformed")],
    )

    Note

    inlets appear in the Airflow lineage graph but are not emitted as constructor arguments in the current template — they drive UI lineage, not runtime behaviour. outlets are emitted and drive data events.

    Data-aware scheduling — consumer DAG triggered by Asset (Airflow 3.0+)¶

    A DAG can be scheduled to run whenever a specific Asset is updated, instead of on a time-based schedule. Set schedule to the Asset URI; Airflow 3 resolves it as an Asset trigger.

    YAML — producer DAG (publishes the Asset):

    version: "1.0"
name: ingestion

dags:
  - id: ingestion_load_customers
    schedule: "0 4 * * *"
    start_date: "2025-01-01"
    catchup: false
    tags: [ingestion]
    default_args:
      owner: data_eng
      retries: 2
      retry_delay_minutes: 5
      email_on_failure: true
    tasks:
      - id: load_customers
        operator: PythonOperator
        params:
          python_callable: "dags.ingestion.load_customers"
        datasets:
          outlets:
            - uri: "s3://data-warehouse/customers/latest"

    YAML — consumer DAG (scheduled on the Asset):

    version: "1.0"
name: analytics

dags:
  - id: analytics_customer_summary
    description: "Rebuild customer summary table whenever customer data is refreshed"
    schedule: "s3://data-warehouse/customers/latest"   # ← Asset URI as schedule
    start_date: "2025-01-01"
    catchup: false
    tags: [analytics]
    default_args:
      owner: analytics_team
      retries: 1
      retry_delay_minutes: 10
      email_on_failure: true
    tasks:
      - id: rebuild_summary
        operator: PythonOperator
        params:
          python_callable: "dags.analytics.rebuild_customer_summary"
      - id: refresh_dashboard
        operator: PythonOperator
        params:
          python_callable: "dags.analytics.refresh_dashboard"
        dependencies: [rebuild_summary]

    Generated Python (consumer DAG constructor):

    with DAG(
    dag_id="analytics_customer_summary",
    description="Rebuild customer summary table whenever customer data is refreshed",
    schedule="s3://data-warehouse/customers/latest",   # ← Airflow 3 resolves as Asset trigger
    start_date=datetime(2025, 1, 1),
    catchup=False,
    ...
) as dag:
    ...

    Note

    Airflow 3 recognises an Asset URI string as the schedule and triggers this DAG automatically each time ingestion_load_customers completes its load_customers task.

    Dynamic task mapping with expand (Airflow 3.0+)¶

    Use expand when each mapped task instance receives a single argument that varies. The generator produces .partial().expand().

    YAML:

    version: "1.0"
name: processing

dags:
  - id: processing_batch_records
    description: "Fetch a list of records and process each one in parallel"
    schedule: "@daily"
    start_date: "2025-01-01"
    catchup: false
    tags: [processing]
    default_args:
      owner: data_eng
      retries: 2
      retry_delay_minutes: 5
      email_on_failure: true
    tasks:
      - id: fetch_records
        operator: PythonOperator
        params:
          python_callable: "dags.processing.fetch_records"

      - id: process_record
        operator: PythonOperator
        params:
          python_callable: "dags.processing.process_record"
        dynamic_map:
          expand:
            record: "{{ fetch_records.output }}"
        pool: processing_pool
        pool_slots: 1
        execution_timeout_minutes: 10
        on_failure_callback: "plugins.alerts.task_failed"
        dependencies: [fetch_records]

      - id: finalize
        operator: PythonOperator
        params:
          python_callable: "dags.processing.finalize"
        trigger_rule: all_done
        dependencies: [process_record]

    Generated Python:

    from dags.processing import fetch_records
from dags.processing import process_record
from dags.processing import finalize
from plugins.alerts import task_failed

    fetch_records = PythonOperator(
        task_id="fetch_records",
        python_callable=fetch_records,
    )

    process_record = PythonOperator.partial(
        task_id="process_record",
        python_callable=process_record,
        pool="processing_pool",
        pool_slots=1,
        execution_timeout=timedelta(minutes=10),
        on_failure_callback=task_failed,
    ).expand(
        record=fetch_records.output,   # ← one task instance per record
    )

    finalize = PythonOperator(
        task_id="finalize",
        python_callable=finalize,
        trigger_rule="all_done",
    )

    fetch_records >> process_record
    process_record >> finalize

    Dynamic task mapping with expand_kwargs (Airflow 3.0+)¶

    Use expand_kwargs when each mapped task instance receives a dictionary of arguments. The upstream task returns a list of dicts; each dict is unpacked as keyword arguments.

    YAML:

    version: "1.0"
name: pipeline

dags:
  - id: pipeline_multi_config_jobs
    description: "Run a job for each configuration returned by the config loader"
    schedule: "0 3 * * *"
    start_date: "2025-01-01"
    catchup: false
    tags: [pipeline]
    default_args:
      owner: platform_team
      retries: 1
      retry_delay_minutes: 10
      email_on_failure: true
    tasks:
      - id: load_configs
        operator: PythonOperator
        params:
          python_callable: "dags.pipeline.load_job_configs"

      - id: run_job
        operator: PythonOperator
        params:
          python_callable: "dags.pipeline.run_job"
        dynamic_map:
          expand_kwargs: "{{ load_configs.output }}"
        execution_timeout_minutes: 30
        dependencies: [load_configs]

      - id: aggregate_results
        operator: PythonOperator
        params:
          python_callable: "dags.pipeline.aggregate_results"
        dependencies: [run_job]

    Generated Python:

    from dags.pipeline import load_job_configs
from dags.pipeline import run_job
from dags.pipeline import aggregate_results

    load_configs = PythonOperator(
        task_id="load_configs",
        python_callable=load_job_configs,
    )

    run_job = PythonOperator.partial(
        task_id="run_job",
        python_callable=run_job,
        execution_timeout=timedelta(minutes=30),
    ).expand_kwargs(load_configs.output)   # ← each dict in the list becomes kwargs

    aggregate_results = PythonOperator(
        task_id="aggregate_results",
        python_callable=aggregate_results,
    )

    load_configs >> run_job
    run_job >> aggregate_results

    Warning

    expand and expand_kwargs are mutually exclusive on a single task. Use expand for a single varying argument; use expand_kwargs when each instance needs a different set of keyword arguments.

    map_index_template — custom mapped task labels (Airflow 3.0+)¶

    By default Airflow labels mapped task instances as task_id[0], task_id[1], etc. map_index_template lets you set a Jinja expression that produces a meaningful label using task context.

    YAML:

    version: "1.0"
name: etl

dags:
  - id: etl_regional_pipeline
    description: "Run the ETL pipeline for each region, with labelled task instances"
    schedule: "0 2 * * *"
    start_date: "2025-01-01"
    catchup: false
    tags: [etl]
    default_args:
      owner: etl_team
      retries: 2
      retry_delay_minutes: 5
      email_on_failure: true
    tasks:
      - id: get_regions
        operator: PythonOperator
        params:
          python_callable: "dags.etl.get_active_regions"

      - id: process_region
        operator: PythonOperator
        params:
          python_callable: "dags.etl.process_region"
        dynamic_map:
          expand:
            region: "{{ get_regions.output }}"
          map_index_template: "region={{ region }}"
        datasets:
          outlets:
            - uri: "s3://data-lake/regions/processed"
        pool: etl_pool
        execution_timeout_minutes: 45
        dependencies: [get_regions]

      - id: merge_regions
        operator: PythonOperator
        params:
          python_callable: "dags.etl.merge_regions"
        trigger_rule: all_success
        dependencies: [process_region]

    Generated Python:

    from airflow.sdk import Asset
from dags.etl import get_active_regions
from dags.etl import process_region
from dags.etl import merge_regions

    get_regions = PythonOperator(
        task_id="get_regions",
        python_callable=get_active_regions,
    )

    process_region = PythonOperator.partial(
        task_id="process_region",
        python_callable=process_region,
        outlets=[Asset("s3://data-lake/regions/processed")],
        pool="etl_pool",
        execution_timeout=timedelta(minutes=45),
    ).expand(
        region=get_regions.output,
    )
    process_region.map_index_template = "region={{ region }}"   # ← UI shows "region=eu-west-1" etc.

    merge_regions = PythonOperator(
        task_id="merge_regions",
        python_callable=merge_regions,
        trigger_rule="all_success",
    )

    get_regions >> process_region
    process_region >> merge_regions

    Note

    The Airflow UI displays each mapped instance as process_region[region=eu-west-1], process_region[region=us-east-1], etc., instead of the default numeric index. The template expression is evaluated at runtime using the task instance context.
