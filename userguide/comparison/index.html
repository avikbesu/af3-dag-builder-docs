    Comparison: af3-dag-builder vs. Astro DAG Factory¶

    Astro DAG Factory is the most widely known YAML-to-DAG tool in the Airflow ecosystem. This page explains the fundamental architectural difference and why af3-dag-builder makes different choices.

    The core architectural difference¶

    DAG Factory works as a Python library that runs inside Airflow. When the Airflow scheduler scans for DAGs, it imports a loader file that reads your YAML and constructs DAG and operator objects in memory on every scan cycle. There are no generated Python files — the YAML is the only source of truth, interpreted at runtime.

    af3-dag-builder works as a compile-time code generator. A Go binary reads your YAML once, resolves environment overrides, and writes real Python .py files to disk. Those files are deployed to Airflow exactly like handwritten DAGs. The generator runs in CI, not in Airflow.

    Feature comparison¶

    Capability af3-dag-builder Astro DAG Factory
    Airflow 3.2.2+ native Built for Airflow 3.x from day one; uses airflow.sdk, airflow.providers.standard.* Built for Airflow 2; Airflow 3 support incomplete
    Dynamic task mapping (3.0+) .expand() and .expand_kwargs() with YAML syntax; map_index_template supported Not supported for Airflow 3
    Airflow 3 Assets (3.0+) Asset inlet/outlet declarations, data-driven scheduling Not supported
    dag_display_name (3.2+) Set a human-readable name independent of dag_id Not supported
    Scheduler overhead Zero — DAGs are static .py files YAML parsed and DAGs rebuilt on every scheduler heartbeat
    Reviewable output Generated .py files committed to git; diffs show exactly what changed No generated files; the runtime behavior is invisible
    Pre-deployment validation python3 -m py_compile on every file; broken configs never deploy No validation before Airflow loads the file
    JSON schema validation Full JSON schema (dags.schema.json) checked in CI No schema; YAML errors fail silently at runtime
    Multi-environment _env overrides on any param; per-env DAG and task enable/disable No built-in environment model
    Environment promotion diff scripts/promote.py shows the exact param and task delta staging→prod Not provided
    Secret detection lint_secrets.py blocks hardcoded passwords and tokens in CI Not provided
    Operator governance Central config/operators/registry.yaml; unknown operators fail CI No registry; typos in operator names fail at runtime
    DAG templates Reusable DAG skeletons with pre_tasks / post_tasks Not provided
    Task library Project-level reusable task snippets with use: Not provided
    Multi-file projects Split large projects across multiple YAML files Not provided
    Generator performance Compiled Go binary; generates hundreds of DAGs in milliseconds Python interpreted at every scheduler scan
    Dependency No runtime dependency added to Airflow Adds dag-factory package to Airflow environment

    When DAG Factory is a reasonable choice¶

    • You are running Airflow 2 with no near-term plan to upgrade.
    • Your team wants the simplest possible setup with no build step.
    • You have only a handful of DAGs and scheduler parse overhead is not a concern.
    • You are already using other Astronomer tooling and want tight integration.

    When af3-dag-builder is the better fit¶

    • You are on Airflow 3 and need native support for Assets, dynamic task mapping, and other Airflow 3 semantics.
    • You want generated files that your team can read, review in pull requests, and audit — not YAML that only becomes visible inside the Airflow process.
    • You need per-environment configuration discipline: different retries, commands, and enabled states across dev, staging, and prod without duplicating YAML.
    • You run multiple projects in one repo and need a governed operator registry and secret detection as CI gates.
    • Scheduler performance matters: you don't want YAML parsing and DAG object construction happening on every heartbeat.
    • You want a promotion workflow where staging→prod changes are diffed and reviewed before deployment.
